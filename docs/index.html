wgsql

github.com/shiahonb777/wgsql · MIT

A SQL aggregation kernel that runs on the user's GPU through WebGPU. Below, the same query — SELECT key, SUM(value), COUNT(*) WHERE value ≥ ? GROUP BY key — runs twice on every slider movement: once on a JavaScript Map in a Web Worker, and once on the GPU. Same data, same code path, ten million rows. Drag the slider and watch the latency column on each side.

The Web Worker is the most generous JavaScript baseline available in a browser. It gets its own thread and never blocks the UI. The latency you see between the two columns is the cost of an aggregation that doesn't fit in CPU cache.

Speed against DuckDB-WASM.

The same GROUP BY, this time as a fixed benchmark. JavaScript and DuckDB-WASM are both in-tab, browser-native baselines. wgsql wins decisively above ~10⁵ distinct keys, where a hash table no longer fits in CPU L2 cache. At low cardinality, the JS Map is hard to beat; we say so on the page rather than hide the runs.
